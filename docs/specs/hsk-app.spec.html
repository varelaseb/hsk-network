HSK app

docs / specs / hsk-app.spec.html

The HSK site as an app a learner adds to the iPhone home screen from Safari: its icon, name, full-screen launch, phone fit, and offline use.

It wraps the network and the bubbles game without changing what either does; its colors and faces come from the shared look.

The site stays static files on GitHub Pages under its project path; the app is those files plus a manifest, icons, and an offline worker.

User stories

As a learner on an iPhone, I add the site to my home screen from Safari and get an app icon and name that say Traditional characters and Zhuyin, Taiwan style, and match the site's look.

As a learner, the installed app opens full screen like a native app: no browser bars, no white flash, no page zoom or bounce, nothing under the notch or home indicator, and the network and the game open inside it.

As a learner, the installed app works with no connection, including its typefaces and word recordings, and it picks up a new version by itself.

As a learner on a phone, the site shows its page quickly, before the graph has finished loading.

As a maintainer, tests prove on every pull request that the app manifest is valid for the site's address and that the offline file list matches the published files.

Modular boundaries

The app shell owns install identity and launch: the manifest, icons, launch images, and the head of each page (theme color, status bar style, viewport, inline first-paint color), plus the page-level touch and safe-area rules. Caller-facing seam: the manifest file and the head lines both pages carry; the network and the game add nothing else to join the app. Dependency direction: self-contained; it reads the shared look's colors and Chinese face and changes no network or game behavior. Observable scope: the home screen icon and name, launch, status bar, and page fit.

The offline worker owns saving the published files, answering requests from the saved copy, and replacing the copy when the version changes. Caller-facing seam: one worker script at the site root, registered by both pages, whose top holds the file list and version. Dependency direction: self-contained; it fetches only the site's own files and holds no word, game, or settings logic. Observable scope: the site working offline and new versions arriving.

The offline list command owns computing the file list and version from the site directory and writing them into the worker script. Caller-facing seam: one standard-library command, run after any site change, and the function the tests call to recompute the list. Dependency direction: self-contained; it reads the site directory only and runs with no network. Observable scope: the worker script's list block and the tests that compare it.

The icon command owns drawing the icons and launch images from the pinned Noto Sans CJK TC release and the look's colors. Caller-facing seam: one maintainer command, run only when the icon or colors change, writing the committed images. Dependency direction: external provider; like the font command it needs a throwaway environment with an imaging library and the font release cache, never CI. Observable scope: the committed icon and launch images.

Delivery runs the app tests with the existing suite on every pull request and publishes the app files with the site directory on every merge to main. Caller-facing seam: the pull request test check and the public address. Dependency direction: external provider GitHub Actions and GitHub Pages, unchanged; the site directory is still published unchanged. Observable scope: check status and the installable live site.

03

Phone fit

The page never moves; only the graph and the game board take gestures.

  • The network pads its search bar by the top and side safe areas and its bottom sheet and Sources footer by the bottom safe area; the graph itself runs edge to edge. The game's existing safe-area rules stay.
  • The network fills the visible screen height, measured as the dynamic viewport, so no strip hides under a toolbar in Safari or shows below the page in the app.
  • The page does not zoom: controls ignore double-tap zoom, the graph takes all pinch and pan, and every text input is at least 16px, as the network already requires.
  • The page does not scroll or bounce; only the results list, the sheet, and the Sources body scroll, each within itself.
  • Every tappable control is at least 44px, as the network and game already require, and taps show no gray highlight flash.
  • Long-pressing a node or a game bubble shows no text selection or callout; card text stays selectable.
04

Offline and updates

One saved copy per version; the version is a hash of every published file.

  1. First visit online: the page registers the worker after it has drawn, so saving never delays first paint; the worker saves every listed file into a cache named by the version, and only a complete save counts.
  2. Every later request for a listed file is answered from the saved copy, ignoring the part after # and any query; opening the site root or the game folder answers with that page.
  3. A request for anything not listed goes to the network, and offline it fails as a browser would; an unknown page address offline shows the network.
  4. When the site changes, the worker script's version changes, so the browser fetches the new worker on the next visit; it saves the new copy in the background.
  5. Once the new copy is complete, the new worker takes over and deletes older copies; the open page keeps running and is never reloaded, and the next open shows the new version.
  6. If a save is interrupted, the old copy, or the network when there is none, keeps serving, and the next visit tries again.
  • The list is every file in the published site directory except the worker script itself, sorted; the version is a short hash over each listed file's path and contents.
  • The list and version are written into a marked block at the top of the worker script by the offline list command, so any site change changes the worker's bytes; a test recomputes both and fails when the block is stale.
  • The worker fetches only the site's own files, so the site still makes no third-party request.
  • Local preview serves the same worker from the site root; it behaves the same on a loopback address.

06

Build and tests

Plain files; the site directory is still published unchanged.

  • New site files: the manifest, the worker script at the site root, and an icons folder; no framework, no bundler, no new runtime dependency.
  • The offline list command is Python standard library only; the repository instructions name it and add it to the data and font refresh steps.
  • The icon command follows the font command's pattern: a throwaway environment, the pinned Noto Sans CJK TC release from the font cache, committed output.
  • Manifest: parses; id, start, and scope resolve inside the site path from the manifest's own address; display standalone; names; colors equal the look's paper and night where named; each icon file exists with the stated pixel size read from its header, one maskable.
  • Heads: both pages link the same manifest and the 180 pixel icon, carry the app-capable and title lines and viewport-fit cover, and set the theme color and inline background to their own look color.
  • File list: the worker's list and version equal the ones recomputed from the site directory.
  • Worker: a complete install saves every listed file, an interrupted one leaves the old copy serving, activation deletes older copies, and no client is reloaded.
  • Static: the existing site reference check covers the manifest and the worker.
  • Phone check: a headless phone viewport loads the network and the game, then loads both again offline, with no console error and no request outside the site.
